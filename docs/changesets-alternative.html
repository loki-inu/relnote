A Changesets alternative without .changeset files

Changesets asks every PR to add a markdown file under .changeset/, then changeset version (usually through a bot's Version Packages PR) turns those files into bumps and per-package CHANGELOG.md entries. If your commits already follow conventional commits with a scope, relnote can read them directly: per-package notes, next version, CHANGELOG.md, package.json bump, and api@1.4.0-style tags. No .changeset folder, no npx changeset, and no bot PR.

Keep Changesets when you want release intent written by people in PRs, automatic bumps of internal dependents, or linked version groups. This page replaces the simpler case: each package releases on its own, and the commit log already says what changed.

Pin the zipapp

Python 3.11+ and git on PATH. Download the v0.3.7 zipapp from the GitHub Release and examples/release.sh from the same tag. No npm install @changesets/cli.

mkdir -p ~/.local/bin
curl -fsSL -o ~/.local/bin/relnote https://github.com/loki-inu/relnote/releases/download/v0.3.7/relnote
chmod +x ~/.local/bin/relnote
curl -fsSL -o release.sh https://raw.githubusercontent.com/loki-inu/relnote/v0.3.7/examples/release.sh
chmod +x release.sh

Commit release.sh into the repo (for example scripts/release.sh). It is plain bash; read it before you run it. You can delete .changeset/ and @changesets/cli once your existing api@x.y.z tags are in place, since relnote starts from the last tag.

Release one package locally

Preview the next tag for one package, then cut it. --path limits commits to that directory, and --tag-prefix picks that package's tags. Use @scope/api@ as the prefix if your tags carry the npm scope.

relnote --next-version --tag-prefix api@ --path packages/api
./release.sh --dry-run --tag-prefix api@ --changelog packages/api/CHANGELOG.md \
  --bump-file packages/api/package.json -- --path packages/api

Drop --dry-run to write it: packages/api/package.json gets the new version, packages/api/CHANGELOG.md gets one new section, and you get a chore(release): api@1.4.0 commit and an api@1.4.0 tag. Nothing is pushed. Add --exec "npm install --package-lock-only --ignore-scripts --silent" if the lockfile records workspace versions (see the npm package guide). Afterwards: git push --follow-tags.

GitHub Actions: pick a package, release it

Save this as .github/workflows/release.yml, list your package directories under options, and use Actions → Release → Run workflow. The action's has-changes output skips the run when that package has nothing unreleased. Action inputs: GitHub Action guide.

name: Release
on:
  workflow_dispatch:
    inputs:
      package:
        description: Package directory name under packages/
        type: choice
        options: [api, web]
permissions:
  contents: write
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - id: relnote
        uses: loki-inu/relnote@v0.3.7
        with:
          path: packages/${{ inputs.package }}
          tag-prefix: ${{ inputs.package }}@
      - name: Install relnote and release.sh
        if: steps.relnote.outputs.has-changes == 'true'
        env:
          V: v0.3.7
        run: |
          mkdir -p "$HOME/.local/bin"
          curl -fsSL -o "$HOME/.local/bin/relnote" "https://github.com/loki-inu/relnote/releases/download/$V/relnote"
          chmod +x "$HOME/.local/bin/relnote"
          curl -fsSL -o "$RUNNER_TEMP/release.sh" "https://raw.githubusercontent.com/loki-inu/relnote/$V/examples/release.sh"
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"
      - name: Bump, changelog, tag, publish
        if: steps.relnote.outputs.has-changes == 'true'
        env:
          GH_TOKEN: ${{ github.token }}
          PKG: ${{ inputs.package }}
        run: |
          set -euo pipefail
          prefix="$PKG@"
          dir="packages/$PKG"
          if [ -n "$(git tag --points-at HEAD --list "$prefix*")" ]; then
            echo "HEAD is already tagged for $PKG; nothing to release."
            exit 0
          fi
          git config user.name "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          bash "$RUNNER_TEMP/release.sh" --tag-prefix "$prefix" \
            --changelog "$dir/CHANGELOG.md" --bump-file "$dir/package.json" -- --path "$dir"
          tag=$(git describe --tags --exact-match --match "$prefix*")
          git push origin HEAD "refs/tags/$tag"
          relnote --tag-prefix "$prefix" --path "$dir" --output "$RUNNER_TEMP/notes.md" --quiet
          gh release create "$tag" --title "$tag" --notes-file "$RUNNER_TEMP/notes.md"

Notes go through a file and --notes-file. Never interpolate the body inside run: (backticks in commit subjects break the shell). Add an npm publish step afterwards if the package goes to npm; trusted publishing is on the npm package guide.

What one run does

Start: packages/api is at api@1.3.2 and packages/web at web@0.4.0. Since then, feat(api): add --json output (#12) touched packages/api and fix(web): handle empty config (#13) touched packages/web. Running the workflow with package: api leaves web alone. packages/api/package.json now says "version": "1.4.0", and packages/api/CHANGELOG.md gets:

## [api@1.4.0] - 2026-11-09

### Features

- **api:** add --json output ([#12](https://github.com/you/monorepo/pull/12)) (`57fc221`) — Ada Lovelace

**Full changelog:** https://github.com/you/monorepo/compare/api@1.3.2...api@1.4.0

The GitHub Release api@1.4.0 gets this body:

## What's changed

### Features

- **api:** add --json output (#12) (`57fc221`) — Ada Lovelace

---

Range: `api@1.3.2` → `api@1.4.0`.

**Full changelog:** https://github.com/you/monorepo/compare/api@1.3.2...api@1.4.0

Both blocks come from running the workflow's last step against a scratch monorepo in relnote's test suite (tests/test_changesets_docs.py, with gh stubbed); your hashes and dates differ. The fix(web) commit is not in the api notes, and the chore(release) commit is not listed.

FAQ

When should I keep Changesets?

Keep Changesets when you want release intent written by people in PRs instead of commit messages, automatic bumps of dependent workspace packages, linked or fixed version groups, pre-release mode, or the Version Packages PR from changesets/action. relnote does not track dependencies between packages.

Do my tags have to change?

No. Changesets tags look like api@1.3.2 or @scope/api@1.3.2. Pass that prefix (api@ or @scope/api@) to --tag-prefix and relnote reads the last tag and prints the next one in the same shape, for example api@1.4.0. More tag shapes: the monorepo guide.

What about package-lock.json or pnpm-lock.yaml?

Add release.sh --exec with your package manager's lockfile-only command, for example --exec "npm install --package-lock-only --ignore-scripts --silent". Tracked files it changes are committed with the release. See the npm package guide.

How do I dry-run?

release.sh --dry-run with the same --tag-prefix, --changelog, --bump-file, and -- --path flags prints the next tag, files, and notes and writes nothing. Version rules: next version.

Are chore(release) commits included in the notes?

No by default. relnote skips chore(release) subjects, even when they touch the package directory. Pass --include-release-commits to keep them.

How is this different from the semantic-release alternative?

The semantic-release alternative and release-please alternative release one version for the whole repo. This page is for monorepos that release packages separately with pkg@x.y.z tags.

Should I pin versions?

Yes. Pin the curl URL and the loki-inu/relnote action to the same tag (this page uses v0.3.7). Floating latest can change behaviour under you.

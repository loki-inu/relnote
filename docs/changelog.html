Generate CHANGELOG.md from conventional commits, without a config file

relnote reads your git history from the latest tag to HEAD, groups feat, fix, and breaking changes, and prepends one release section to CHANGELOG.md. Your header and older entries are left exactly as they were.

relnote on GitHub · v0.2.0 release · Compare to git-cliff

Install

pip install git+https://github.com/loki-inu/relnote.git
relnote --version   # relnote 0.2.0

Python 3.11+ and git on PATH. No third-party packages, no network calls, no config file.

Add the next release

relnote --changelog CHANGELOG.md --changelog-title v1.3.0
git add CHANGELOG.md && git commit -m "docs: changelog for v1.3.0"
git tag v1.3.0

stdout still prints the GitHub Release body, so one run gives you both. Add -q to only touch the file. Pass --since v1.2.0 to pick the range by hand and --date 2026-10-08 to pin the date (default is today in UTC). Without --changelog-title, the title is the --until ref, or Unreleased when that is HEAD.

What gets written

# Changelog

All notable changes to this project are documented in this file.

## [v1.3.0] - 2026-10-08

### Breaking

- **api:** drop the v1 endpoint (`a1b2c3d`) — Ada Lovelace
  - BREAKING CHANGE: clients must call /v2

### Features

- **cli:** add --json output (`d4e5f6a`) — Ada Lovelace

### Fixes

- handle empty config (`b7c8d9e`) — Grace Hopper

**Full changelog:** https://github.com/you/project/compare/v1.2.0...v1.3.0

## [v1.2.0] - 2026-09-01
…

Illustrative output from a made-up history. A missing file is created with the # Changelog header. The new section goes above the first ## heading, after any preamble. The compare link appears when origin is a github.com remote.

Safe to re-run

  • If CHANGELOG.md already has ## [v1.3.0], relnote exits 1 and changes nothing. A retried CI job cannot add the release twice.
  • An empty range (no commits after filters) exits 1 before the file is touched.
  • Merge commits are skipped by default, --no-bots drops dependabot and renovate, and subjects that look like tokens or keys are never written.

In GitHub Actions

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- id: relnote
  uses: loki-inu/relnote@v0.2.0
  with:
    changelog: CHANGELOG.md
    changelog-title: ${{ github.ref_name }}
# then commit CHANGELOG.md in a later step or open a PR with it

The notes output is still the Release body. The action edits the file in the runner only; committing it is up to your workflow.

With the GitHub CLI

gh extension install loki-inu/gh-relnote
gh relnote create v1.3.0 --draft -- --changelog CHANGELOG.md --changelog-title v1.3.0

Creates the draft Release and updates CHANGELOG.md from the same notes. See gh relnote.

relnote vs git-cliff for CHANGELOG.md

relnote --changeloggit-cliff
ConfigNonecliff.toml with Tera templates
How the file changesPrepends the new release onlyRegenerates from history, or prepends with --prepend
InstallStdlib Python, or the gh extensionRust binary, cargo, npm, pip, and more
Release body tooYes, same run, on stdoutSeparate invocation or template
Version bumpNoYes, --bump

Pick git-cliff if you want custom templates, commit parsers, or a computed next version. Pick relnote if you want sensible Keep a Changelog sections and a Release body with nothing to configure.

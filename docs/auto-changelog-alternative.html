An auto-changelog alternative without a full-history rebuild

auto-changelog (auto-changelog on npm, cookpete/auto-changelog) generates a changelog from git tags and commit history. The published package is 2.7.0. Its README says it is used by Modernizr, Netlify, Neutrino, and Velocity.js. If the commits already follow conventional commits and you want a GitHub Release body plus one new CHANGELOG.md section, relnote does that from the local git log: no Node package, no Handlebars template, and no config file.

Keep auto-changelog when the changelog should be rebuilt from every semver tag, when you want a Handlebars template (compact, keepachangelog, json, or your own), when merged pull requests and closed issues are the list you want, or when those links must work for GitLab, BitBucket, or Azure DevOps. The README's suggested hook is a package.json version script, so npm version refreshes CHANGELOG.md and stages it. Keep that path if the bump should stay npm version.

relnote is the better fit when commits are already conventional, including squash-merged titles such as feat: … (#12), and you want those subjects grouped with no template and no three-commit cap. It is also the fit when older changelog entries must stay untouched, when the release tooling should not be a Node package, and when the next step is a GitHub Release body. It is a poor fit when the history you care about is merge commits: those are omitted by default, while auto-changelog is built to list them.

Install

What you are leaving, from the 2.7.0 README:

npm install -g auto-changelog
auto-changelog

Or as a dev dependency, which is the README's other install: npm install auto-changelog --save-dev.

Python 3.11+ and git on PATH. The download is the v0.3.8 zipapp from the GitHub Release, the same pin as the single-file install. From a checkout, python3 -m relnote is the same CLI. pip install git+https://github.com/loki-inu/relnote.git is the other install on the offline release notes page. Remove auto-changelog from devDependencies when nothing else imports it. relnote does not read .auto-changelog or the package.json key.

mkdir -p ~/.local/bin
curl -fsSL -o ~/.local/bin/relnote https://github.com/loki-inu/relnote/releases/download/v0.3.8/relnote
chmod +x ~/.local/bin/relnote

Release body, next version, CHANGELOG section

Three separate invocations, the same flags as the offline guide, the next version guide, and the CHANGELOG.md guide. Nothing is pushed, and no GitHub API is called. --since REF starts somewhere other than the latest tag, which is the relnote equivalent of --starting-version for a single range.

python3 -m relnote --next-version
python3 -m relnote --output notes.md --quiet
python3 -m relnote --changelog CHANGELOG.md --changelog-title v1.4.0 --quiet

--next-version prints one line, such as v1.4.0. --output notes.md --quiet writes the Release body and prints nothing. --changelog prepends one section. With --changelog-title v1.4.0 on an untagged HEAD, that section's compare link ends at v1.4.0 (v0.3.6+). Without --changelog-title, an untagged HEAD is titled Unreleased. The command does not commit the file, and it does not read package.json the way auto-changelog -p does.

What those commands write

Start: the last tag is v1.3.2, then feat: add --json output (#12) and fix: handle empty config (#13). --next-version prints v1.4.0 (a feat is a minor bump). notes.md is the Release body. Because HEAD is not tagged yet, the range ends at HEAD:

## What's changed

### Features

- add --json output (#12) (`4a5b395`) — Ada Lovelace

### Fixes

- handle empty config (#13) (`7e08d2c`) — Ada Lovelace

---

Range: `v1.3.2` → `HEAD`.

**Full changelog:** https://github.com/you/project/compare/v1.3.2...HEAD

CHANGELOG.md gains this section above the previous entries. (#12) becomes a pull request link when origin is a github.com remote (v0.3.5+):

## [v1.4.0] - 2026-11-18

### Features

- add --json output ([#12](https://github.com/you/project/pull/12)) (`4a5b395`) — Ada Lovelace

### Fixes

- handle empty config ([#13](https://github.com/you/project/pull/13)) (`7e08d2c`) — Ada Lovelace

**Full changelog:** https://github.com/you/project/compare/v1.3.2...v1.4.0

Both blocks come from running those three commands against a scratch repository in relnote's test suite (tests/test_auto_changelog_docs.py). Your hashes and the date differ. A squash-merged pull request whose title is already feat: … (#12) is one commit, so it shows up as one line. Details: squash-merged PR titles.

Migration

  1. Install the zipapp above and pin it to v0.3.8. Stop running auto-changelog in CI and locally.
  2. Leave the current CHANGELOG.md in the repo. The next --changelog run inserts one section before the first ## heading. Older sections are not rewritten, and there is no commit-limit of 3 on that section. The <!-- auto-changelog-above --> comment is ordinary preamble to relnote; it stays above the new section. Delete the comment once you no longer regenerate the file.
  3. Remove auto-changelog from the version script. The 2.7.0 README's example is auto-changelog -p && git add CHANGELOG.md. npm version will no longer refresh the changelog. Two replacements: keep npm version for the bump and run the three relnote commands yourself, or use examples/release.sh for the bump, the section, the commit, and the tag.
  4. Publish the GitHub Release with the workflows on the Action guide, copied below. relnote still does not push.

examples/release.sh is the local stand-in for that version script plus the tag. --dry-run prints the plan and writes nothing. --bump-file package.json sets the first version line. For an npm package that also commits package-lock.json, the npm package guide adds --exec. Nothing in the script is pushed.

curl -fsSL -o release.sh https://raw.githubusercontent.com/loki-inu/relnote/v0.3.8/examples/release.sh
chmod +x release.sh
./release.sh --dry-run --bump-file package.json
./release.sh --bump-file package.json

That URL is examples/release.sh on the v0.3.8 tag. The v0.3.8 release assets are relnote, relnote.pyz, and SHA256SUMS, so the script is not a release asset. It calls relnote on PATH.

Monorepos: auto-changelog 2.7.0 ships --autodetect-monorepo-disabled, which defaults to true, so detection is off. --no-autodetect-monorepo-disabled turns it on. The README says a detected package (a repository.directory field, or an ancestor package.json with npm workspaces) takes its tag prefix from the package name unless one is already set, and strips that prefix from headings. The option is documented to default to false in the next major. relnote does not autodetect workspaces. Pass --path and --tag-prefix (or release.sh --tag-prefix). Guide: monorepo release notes.

Draft a Release when the tag is pushed

This is the tag-push workflow from the GitHub Action guide and from examples/draft-release.yml. Copy it to .github/workflows/draft-release.yml. Push a tag such as v1.4.0 and a draft Release appears with the notes since the previous tag. You review it and press Publish. There is no auto-changelog step and no npm install.

name: Draft release

on:
  push:
    tags:
      - "v*"

jobs:
  draft:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - id: relnote
        uses: loki-inu/relnote@v0.3.8
      - uses: softprops/action-gh-release@v2
        with:
          draft: true
          name: ${{ github.ref_name }}
          body: ${{ steps.relnote.outputs.notes }}

fetch-depth: 0 is required so the checkout has tags. contents: write is for the release step. The relnote step only reads the checkout. On a tag push, HEAD is the new tag, so the range and the compare link end at that tag (v0.3.4+), not at HEAD.

No third-party release action? The guide's GitHub CLI step passes the notes through the environment, not inline in the script (commit subjects contain backticks):

      - run: gh release create "$GITHUB_REF_NAME" --draft --title "$GITHUB_REF_NAME" --notes "$NOTES"
        env:
          GH_TOKEN: ${{ github.token }}
          NOTES: ${{ steps.relnote.outputs.notes }}

Or create the Release from a button

This is the workflow_dispatch job from the same guide. next-version is the tag. has-changes is false when there is nothing new, and the step still succeeds, so the gh step is gated on it. gh release create makes the tag at --target.

name: Release
on:
  workflow_dispatch:
permissions:
  contents: write
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - id: relnote
        uses: loki-inu/relnote@v0.3.8
      - if: steps.relnote.outputs.has-changes == 'true'
        run: gh release create "$TAG" --target "$GITHUB_SHA" --title "$TAG" --notes "$NOTES"
        env:
          GH_TOKEN: ${{ github.token }}
          TAG: ${{ steps.relnote.outputs.next-version }}
          NOTES: ${{ steps.relnote.outputs.notes }}
      - if: steps.relnote.outputs.has-changes != 'true'
        run: echo "Nothing to release since the last tag."

Set fail-on-empty: true if an empty range should fail the step. An unknown since ref still fails. Inputs and outputs: the Action guide.

FAQ

When should I keep auto-changelog?

Keep it when you want CHANGELOG.md rebuilt from semver tags, Handlebars templates, merged pull requests and closed issues in the log, or the npm version hook. Also keep it when compare and issue links must cover GitLab, BitBucket, or Azure DevOps. relnote prepends one section, groups conventional commits with no template, and builds a compare link when origin is a github.com remote.

Does relnote rebuild CHANGELOG.md from every tag?

No. auto-changelog rebuilds the file from tagged versions. relnote inserts one section before the first ## heading and leaves older sections as they were. A duplicate title is refused. The command does not commit.

Does this replace npm version?

Not by itself. auto-changelog does not choose the next version; the documented setup runs auto-changelog -p inside the package.json version script so npm version updates the changelog. relnote --next-version only prints a tag. examples/release.sh --bump-file package.json is the local bump, changelog, commit, and tag. You can also keep npm version and stop calling auto-changelog.

How is this different from the conventional-changelog and git-cliff pages?

The conventional-changelog page is for conventional-changelog presets and commitizen prompts. The git-cliff page is for a Rust binary, cliff.toml, and Tera templates. This page is for the npm package auto-changelog: a Handlebars changelog rebuilt from semver tags, with a default commit-limit of 3.

Should I pin versions?

Yes. Pin the curl URL and the loki-inu/relnote action to the same tag (this page uses v0.3.8). The auto-changelog facts here are from the published 2.7.0 README and npm package, not from an unreleased major. Floating latest on the relnote zipapp can change behaviour under you.
